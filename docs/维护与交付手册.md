# Writable Book Wiki 维护与交付手册

适用：0.1.2 起，当前 0.1.4，Minecraft 1.21.1 / NeoForge 21.1.250。架构与功能入口见 [系统性重构与架构验收](2026-10-29-系统性重构与架构验收.md)。

## 开发前

先读当前需求、README 和与所改功能有关的验收记录。界面是 Word 式所见即所得书页；阅读与编辑共用文档和排版，区别主要是权限和工具栏。不能为了方便实现而恢复 LDLib2、改变纸宽、把图片塞成文字或把个人批注上传为正文。

Java 使用 21，构建使用仓库 Gradle Wrapper。已有缓存时可添加 `--offline`；新电脑首次构建需要联网下载 NeoForge、映射和测试依赖，不应一开始强制离线。

Windows 示例：

```powershell
$env:JAVA_HOME='你的 Java 21 安装目录'
.\gradlew.bat verifyAll --no-daemon --no-problems-report --console=plain
```

本工作区的 Java 21 为 `G:\Games\MC\JAVA\JAVA21`。这是开发机路径，不写入正式 Mod，也不是其他电脑必须具备的盘符。

## 修改流程

1. 找到功能入口，先复现或写出可以判定成功/失败的场景。
2. 判断属于核心规则、文件持久化、格式适配、协议还是界面。下层不能调用上层窗口或网络协调器。
3. 修改一个完整流程，连同输入、校验、操作、保存与反馈一起检查；按钮和快捷键必须走共同规则。
4. 检查所有调用者和失败路径，包括原文档未保存、异步响应过期、离线与窗口替换。
5. 跑相关测试，再跑 `verifyAll`。改变窗口、排版、会话或协议时运行客户端检查。
6. 更新功能入口、版本变化、测试结果与实际限制；不要把“构建成功”写成“所有多人/视觉场景完成”。

新增编辑操作时，先在 `client/editor/EditorCommand` 定义命令，在 `EditorRibbon` 选项卡中安排按钮，在窗口 `performCommand` 接入执行。快捷键映射也返回这个命令；不要在正文和表格各复制一次格式实现。文本选择、剪贴板和纯文本备注继续由当前焦点处理；子框先于正文接收 Esc。

批注的输入内容和已成功保存的列表由 `AnnotationWorkspace` 持有。读取失败不可写空列表覆盖原文件；写失败不能清空输入、切换到另一个批注、关闭窗口或继续提交正文。正文变更后调用 `rebase` 更新锚点；显式保存调用 `saveVersion`，不改旧内容版本的批注文件。普通关闭失败可重试；系统强制结束或断电的未写入草稿恢复不在当前保障内。

纯样式或文档调整不必新增复述实现的测试。状态、存储格式、协议、异常处理及编辑行为变化必须有实际回归场景。

## 自动检查入口

| 命令 | 检查内容 |
| --- | --- |
| `./gradlew.bat :core:test` | 文档、编辑命令、结构、Hash、Unicode、分页和固定旧版 EWD |
| `./gradlew.bat :local:test` | 本地存储、批注、缓存、图片、DOCX 与传输缓冲 |
| `./gradlew.bat verifyArchitecture` | 四模块依赖方向、跨层引用、包路径、文件增长、协议和排版职责边界 |
| `./gradlew.bat verifyReleaseJar` | JAR 名称/版本、合并模块、元数据、测试和无关依赖排除、SHA-256 |
| `./gradlew.bat verifyAll` | 非 GUI 回归、架构、完整 NeoForge 构建和产物检查 |
| `./gradlew.bat verifyClientSmoke -PeditorSmoke` | 启动真实客户端、执行输入/渲染/协议/生命周期检查并自动退出 |
| `./gradlew.bat :neoforge:serverSmokeJar` | 构建独立测试 Mod；仅放入隔离验证服务器，不交付玩家 |
| `./gradlew.bat verifyLecternSmoke -PeditorSmoke -PlecternSmoke` | 对预先启动的本机隔离测试服执行真实 TCP 讲台操作；要求新生成 PASS |

本地可在这些命令后加 `--offline --no-daemon --no-problems-report --console=plain`。正常启动游戏用 `./gradlew.bat :neoforge:runClient`。

`verifyClientSmoke` 会先删除上次自动测试的结果标记，结束后要求本次生成 `PASS`。仅运行 `runClient` 的 Gradle 成功退出并不能证明测试通过。不要拿旧结果文件代替新检查。

结果位置：

- `core/build/reports/tests/test/index.html`、`local/build/reports/tests/test/index.html`。
- `build/reports/release-verification.txt`。
- `neoforge/run-editor-smoke/editor-smoke-results/result.txt` 与同目录截图。
- `neoforge/run-editor-smoke/logs/latest.log`。

自动客户端使用独立的 `run-editor-smoke` 游戏目录，不进入玩家正式世界。操作系统剪贴板相关测试可能改变测试期间的剪贴板内容。

讲台流程由 `LecternBookSupport` 处理放入前校验，原版 `LecternMenu` 持有书槽/页码/取书权限，`LecternDocumentSession` 管理只读生命周期，`ClientLecternBooks` 接管 Wiki 书的讲台界面。原版书保持原版界面。新请求 `network/LecternOpenRequest` 绑定服务器菜单 ID 和书籍指针；正文与图片复用原传输队列。测试服安装、三种验收阶段及证据边界见 [0.1.4 讲台验收](2026-10-29-讲台共享阅读-0.1.4.md)。

## CI 和兼容样本

`.github/workflows/verify.yml` 在 Windows + Java 21 上执行 `verifyAll`，保留测试报告和通过检查的 JAR；不会自动发布版本，也不运行需要图形环境的客户端检查。

固定兼容样本是测试契约：

- `core/src/test/resources/compatibility/release-0.1.1.ewd.base64` 由未修改的 0.1.1 JAR 生成，包含合成内容。
- `neoforge/src/editorSmoke/resources/protocol-v1.properties` 由同一旧 JAR 的包编码器生成，覆盖原有 14 类消息；0.1.4 新增的讲台打开请求由真实 TCP 验收覆盖。
- `local/src/test/resources/docx/independent.docx` 是原有 DOCX 独立样例，继续保留。

不要为了让失败测试变绿而用当前实现重生成兼容样本。确需改变文件或协议时，先明确版本、读取/迁移策略、双版本兼容范围和恢复步骤。维护工具参数 `-PprotocolBaselineJar=<旧 JAR 绝对路径>` 只用于有意采集已审定的旧协议样本；它输出测试目录文件，不自动覆盖仓库样本，正常验收不要加此参数。

架构检查是源码/构建规则检查，不是完整 Java 调用图分析，也不会验证反射生成的依赖。已有大类例外写在 `gradle/verification.gradle`，提升上限必须说明原因；新增代码优先进入对应功能组件。

## 交付

1. 修改 `gradle.properties` 中的版本并更新当前 README。不要覆写已发布版本的同名 JAR。
2. 完成 `verifyAll`；涉及 UI/协议则再完成 `verifyClientSmoke -PeditorSmoke`。
3. 从 `neoforge/build/libs/` 取名称包含 `NeoForge-1.21.1.jar` 的正式包；不要给玩家 `sources` JAR。
4. 将文件与 `build/reports/release-verification.txt` 的大小和 SHA-256 对照。
5. 发布时附上 MC/NeoForge/Java 版本、功能变更、验证范围和已知限制。源码及 CI 更新不等于 JAR 已发布；上传需要对应发布任务授权。

构建会把内部模块合进一个 Mod，不要求安装 LDLib2。自动检查排除测试驱动、协议测试数据、DOCX 样例与 Java 源文件进入正式包。

## 备份哪些数据

| 要保留的内容 | 需要备份的位置 |
| --- | --- |
| 世界中实体书正文、图片、书目索引及物品指针 | **完整世界存档**；不能只拷贝 JAR |
| 玩家个人批注、图片缓存、界面布局、纸色和 F8 预览 | 当前游戏实例的 `config/writablebookwiki/` |
| 服务器分发设置 | 当前游戏实例的 `config/writablebookwiki-server.toml` |
| 开发源码和测试 | 项目源码、Gradle 配置、测试资源、文档；不要只留 build 输出 |

实体书正文在 `<world>/writablebookwiki/documents/`，图片在 `<world>/writablebookwiki/assets/`，索引在 `<world>/data/writablebookwiki_book_index.dat`。物品指针还在世界/玩家存档中，因此恢复世界时要作为整体处理。服务器上的书籍需要备份服务器世界；玩家电脑里的缓存不能替代它。

PCL2 等启动器导出时，世界和个人配置是否包含在整合包中取决于勾选项。只导出地图可以保留该地图的共享书籍，但不包含玩家本机的个人批注与 UI 偏好。

## 本轮源码和程序回退

0.1.4 讲台接入前的 0.1.3 JAR 和代码快照位于 `backups/lectern-before-0.1.4/`；恢复源码使用保留模块路径的 **`source-rooted.zip`**。旁边最初的 `source.zip` 没有保留各模块的上级目录，不能直接按工程解压恢复。0.1.3 JAR SHA-256：`01ec5025f09239bb2b64fa6530697cfe639db8683789c56aab14f26d13de3dc8`。降级前先取回讲台中的 Wiki 书并备份完整世界；旧版本不具备新的讲台支持。

0.1.3 之前的源码和已验收 0.1.2 JAR 保存在 `backups/refactor-0.1.2-before-ui/`。其中 `source.zip` 含源码、测试、构建与文档；旧 JAR 的 SHA-256 为 `404c6dd1b434a84601139d025145f749eaa446ce6ec6da94faeb5686a50d2a9c`。本轮结果见 [0.1.3 验证记录](2026-10-29-输入与批注重构-0.1.3.md)。

更早的架构重构前快照位于 `backups/refactor-20261029/`：

- `source.zip`：修改前源码、构建脚本、测试和文档。
- `Writable Book Wiki-0.1.1-NeoForge-1.21.1.jar`：旧正式程序。
- `client-smoke/`：修改前自动客户端结果和截图。

此目录已从构建输出中单独复制并核对 SHA-256，常规 `clean` 不会删除；已列入 Git 忽略，不上传。它不是玩家世界备份，重要备份仍应另存其他磁盘。当前工作区没有 Git 初始提交，因此不能依赖 `git reset` 恢复这次工作。

源码恢复时先把 `source.zip` 解压到一个新的空目录，核对内容并构建，再决定是否切换开发目录；不要解压覆盖仍有未保存改动的工作区。恢复程序时先退出游戏/停止服务器，备份完整世界及上述配置，再替换为旧 JAR，保证 mods 中只有一个 Writable Book Wiki 版本。本轮不改变 EWD/协议/数据路径，可在副本世界验证旧程序读取；不要宣称单文件原子写能保证世界整体断电恢复。

如果只是缓存损坏，可以在游戏退出后备份并移走对应 Hash 缓存，让服务器重新下发；不要把正式世界的 documents/assets 当缓存清空。数据恢复先在副本进行。

## 发布前人工抽查

客户端自动检查通过后，仍需在复制的世界和真实多人环境抽查：创造/生存拿书、未锁定编辑、锁定与创造解锁、修改副本独立分叉、保存确认前断线、再次登录、同服另一玩家打开图片与表格、个人批注留在本机，以及 PCL2 整包迁移。自动窗口测试不替代这些场景。

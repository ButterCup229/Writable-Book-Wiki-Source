# Writable Book Wiki 0.1.3：输入与批注重构

日期：2026-10-29。运行目标：Minecraft 1.21.1 / NeoForge 21.1.250 / Java 21。此轮在已经验收的 0.1.2 上继续改进；只在本地交付，没有执行 GitHub 上传。

## 玩家可见的修复

| 问题 | 现在的行为 |
| --- | --- |
| 本地批注写入失败，点击正文或退出仍会清空输入 | 保留草稿、选区和独立撤销记录；显示失败提示。存储恢复后再次切换/关闭会重试，成功后交回焦点 |
| 锁定确认框打开时字符与右键仍落到正文 | 确认框优先处理输入；正文字符、编辑快捷键、右键、滚动和拖动均被挡住。Esc 先关闭确认框 |
| 表格选中文字后 Ctrl+Shift+X 实际执行剪切 | 走统一的删除线命令，文字和剪贴板保留，支持正文历史的撤销 |
| 修改顶部书名时 Ctrl+S 被吞掉 | 结束书名输入并调用原有确认保存流程 |
| 批注粘贴连续空行被合并 | 规范 Windows 换行符后保留空行，与表格文本输入共用清理规则 |
| 批注按显示行定位可能落在 emoji 或组合字符中间 | 光标定位到完整字符边界，避免下一次删除拆坏字符 |

读取已有批注文件失败时保留原文件，不把空列表覆盖回去。此状态下正文保存会提示本地批注未提交，需先恢复文件可读性后重开文档；不会静默丢弃已有评语。

## 内部职责

- `local.annotation.AnnotationWorkspace`：个人批注列表、编辑草稿、按原文位置排序、正文版本锚点历史、命名空间和版本保存。它只依赖核心和本地存储，不知道 Minecraft 窗口或发包接口。正文撤销恢复原始锚点；编辑中的评语在锚点重排后仍跟随同一段内容。
- `neoforge.client.editor.EditorCommand`：按钮、提示和快捷键共享具名命令；移除窗口里通过数字索引猜测操作的实现。
- `neoforge.client.editor.EditorRibbon`：选项卡、按钮几何、绘制与命中。它不持有正文、不执行修改，也不保存文件。
- `NativeWikiScreen.performCommand`：按钮与正文/表格格式快捷键的共同执行入口。普通文本的选择和剪贴板仍按当前焦点处理，纯文本批注拥有自己的撤销。
- `TextNavigation.boundaryAtOrBefore`：对鼠标命中或上下移动得到的 UTF-16 位置进行完整字符边界修正。

工具栏布局、按钮大小、纸宽、阅读/编辑共用排版和 MC 书页风格保持。Ctrl+Shift+L 继续“应用无序列表”，按钮可以切换列表开关；这一已有差异明确保留。

窗口类从 5,043 行减至 4,823 行；架构门槛由 5,100 降到 4,900。新增约束阻止工具栏反向调用窗口/存储/网络，也阻止私人批注状态访问共享正文存储。仍未宣称大窗口类已完全整理完毕。

调试过程中两次客户端运行因测试驱动适配未完成而中止：图片用例继承了前一个只读场景，另一个断言仍反射旧的数字命令接口。已修复测试隔离及调用接口，保留全部原断言语义，最终全量通过。

## 本轮边界

实际客户端测试在隔离的开发运行时中加载各模块，产物另做合并内容与元数据校验；本轮未把新 JAR 安装进用户正式整合包或正式存档。未新增真实双端局域网、专用服务器、输入法专项、多显示器和 PCL2 迁移验证。

草稿保护覆盖正常输入、切换焦点和正常退出时的写入失败；不承诺系统强制结束、外部强制替换窗口或断电后恢复尚未落盘的输入。没有借这轮重构增加布局改版或其他功能。
